# 일일 브리핑 작성 규칙과 예약 작업 지시문

대시보드(클로드 아티팩트)의 "브리핑" 탭은 저장소의 `reports/briefing/latest.md`를 GitHub 커넥터로 읽어 표시합니다. 브리핑 글은 클로드 예약 작업이 매일 작성해 저장소에 커밋합니다. 이 문서는 그 파일의 형식과 예약 작업에 넣을 지시문을 정리합니다.

## 1. 파일 위치와 형식

| 항목 | 내용 |
|---|---|
| 날짜별 파일 | `reports/briefing/<YYYY-MM-DD>.md` (작성일, 한국 시간 기준) |
| 최신 파일 | `reports/briefing/latest.md` (날짜별 파일과 같은 내용을 덮어씀) |
| 형식 | 마크다운. 대시보드가 지원하는 문법은 제목(`#`, `##`, `###`), 문단, 글머리 목록, 번호 목록, 표, 인용(`>`), 굵게, 기울임, 인라인 코드, 링크입니다. HTML 태그는 표시되지 않습니다 |
| 첫 줄 | `# 리밸런스 브리핑 <YYYY-MM-DD>` |
| 둘째 문단 | `기준 데이터: <as_of> 종가 보유 내역 (SOXX, QQQ, IGV).` 한 줄 |
| 본문 | `## 한 줄 요약`, `## SOXX`, `## QQQ`, `## IGV`, `## 확인할 것`의 다섯 절 |

본문은 숫자의 나열이 아니라 해석이어야 합니다. 숫자는 대시보드의 보드·노트·트랙 탭이 이미 보여주므로, 브리핑은 "무엇이 바뀌었고, 참조일까지 유지되면 무슨 일이 생기며, 내일 무엇을 봐야 하는지"를 씁니다. 분량은 전체 700자에서 1,500자 사이가 적당합니다.

## 2. 입력 자료

예약 작업은 GitHub 커넥터로 다음 파일을 읽습니다. 저장소는 `tlzkrh1029/etf-rebalancing-tracker`, 브랜치는 `claude/exciting-allen-9b4nx6`입니다.

- `reports/summary.json`: 당일 분석 요약. ETF별 `as_of`, `caps`(지표, 위반, 강제 매도·매수 목록, QQQ 특별 리밸런스 트리거), `next_events`(참조일과 매매일, 남은 거래일), `decomposition`(자금 배율 k, 가격 효과와 주식수 효과 합계, 상위 변동 종목, 실제 매매 종목), `warnings`.
- `reports/history.json`: 일자별 지표와 상위 종목 비중 경로. 며칠째 초과가 이어지는지, 초과폭이 커지는지 줄어드는지를 판단하는 데 씁니다.
- `reports/briefing/latest.md`: 전날 브리핑. 같은 말을 반복하지 않고 변화를 쓰기 위해 읽습니다.

## 3. 예약 작업 지시문 (그대로 붙여 넣기)

```
너는 ETF 리밸런스 트래커의 일일 브리핑 작성자다. GitHub 커넥터로 저장소 tlzkrh1029/etf-rebalancing-tracker (브랜치 claude/exciting-allen-9b4nx6)의 reports/summary.json, reports/history.json, reports/briefing/latest.md를 읽어라.

summary.json의 generated_utc와 각 ETF의 as_of를 확인하고, latest.md의 기준 데이터 날짜와 같으면 새 보유 내역이 아직 없는 것이므로 아무것도 쓰지 말고 "새 데이터 없음"이라고만 보고하라.

새 데이터가 있으면 docs/briefing.md의 형식대로 한국어 브리핑을 작성하라. 규칙:
1. 첫 줄은 "# 리밸런스 브리핑 <오늘 날짜 YYYY-MM-DD, 한국 시간>", 둘째 문단은 "기준 데이터: <as_of> 종가 보유 내역 (SOXX, QQQ, IGV)." 한 줄이다.
2. 절은 "## 한 줄 요약", "## SOXX", "## QQQ", "## IGV", "## 확인할 것" 순서다.
3. 숫자를 나열하지 말고 해석을 써라. 전날 브리핑과 비교해 무엇이 바뀌었는지, 상한 초과가 며칠째 이어지는지(history.json으로 센다), 참조일까지 유지되면 강제 매매 규모가 어떻게 되는지, 실제 매매(classification이 flow_only가 아닌 종목)가 있었는지, 특별 리밸런스 트리거(QQQ)에 변화가 있는지를 쓴다.
4. 비중은 소수 둘째 자리 퍼센트, 비중 변화는 pp, 금액은 달러로 쓴다. 추측은 추측이라고 밝힌다.
5. 완성된 글을 reports/briefing/<오늘 날짜>.md 와 reports/briefing/latest.md 두 파일로 저장소에 커밋하라. 커밋 메시지는 "briefing: <오늘 날짜>"로 한다.
6. 끝으로 "## 한 줄 요약" 절의 내용만 답변으로 보고하라.
```

## 4. 실행 시각

GitHub Actions가 평일 14:10 UTC(한국 시간 23:10)에 전 거래일 보유 내역을 저장하고 18:10 UTC(다음 날 03:10)에 재시도합니다. 브리핑 예약 작업은 두 실행이 모두 끝난 뒤인 한국 시간 화요일부터 토요일 06:10에 돌리는 것을 권합니다. 미국 휴장일 다음 날은 새 데이터가 없어 "새 데이터 없음"으로 끝납니다.

## 5. 대시보드에서 보이는 방식

대시보드는 열릴 때 `latest.md`를 읽어 "브리핑" 탭에 표시하고, `reports/briefing/` 폴더 목록을 읽어 지난 브리핑을 날짜별로 고를 수 있게 합니다. 예약 작업이 커밋하면 다음에 페이지를 열 때 반영되고, 열어 둔 상태에서는 "다시 읽기" 버튼으로 갱신합니다.
